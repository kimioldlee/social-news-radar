# 站点解析规则与栏目清单

本文件记录各站的页面形态、稿件 URL 格式、可用栏目入口与实测踩坑结论。新增或修复采集源时先读这里。

## 通用约定

- parser 接口：`parse_xxx(body, source) -> list[dict]`。统一用 `make_item(source, title_inner_html, url, date=..., note=...)` 构造结果；它负责标题清洗、长度截断、关键词打标与批次标记。
- 源配置字段：`name` / `url` / `parser` / `column` / `media` / `media_type` / `mode` / `recent_only` / `enabled` / `note`。
  - `mode=keyword`（默认）：只保留命中 `keywords` 的条目；若一条都没命中，留前 8 条便于浏览。
  - `mode=all`：全部保留，适合本身就是调查稿聚合的专题页。
  - `recent_only=false`：跳过时间窗过滤，适合更新慢、但历史稿仍有价值的栏目。
- 请求头带完整 UA / Accept / Accept-Language，`Referer` 按目标域名动态设置；每源间隔 1.2 秒，单线程，失败自动跳过。
- 清洗：标题剥离「来源 + 日期 / 阅读量 / 栏目名」尾串，以及 `#话题#` 前缀；去重按 URL 精确匹配 + 标题去标点后前 18 字模糊匹配（同一事件多家转载只留一条）。

## 封面新闻（parser: thecover）

- 首页 `https://www.thecover.cn/` 与专题页均为 SSR，稿件链接 `/news/<加密ID>`。
- **ID 内含 `/`、`+`、`%2B`、`==` 等字符，必须原样拼接，不能 urlencode 或删斜杠**；个别专题页 ID 前多一个 `/`（`/news//xxx`），需规范化为 `/news/xxx`。
- 「封面深镜」调查稿聚合专题（最贴近深度调查选题）：
  - 深度调查 `https://www.thecover.cn/getSubjectById/16060?skId=12601`
  - 封面调查 `https://www.thecover.cn/getSubjectById/15624?skId=12303`
- 特色 IP 栏目：封面深镜（深度调查）、追踪到底（消费）、人间事儿、封面评论、云求助 / 云投诉。
- 首页混有大量央媒外链，正则只取 `/news/` 相对链接即可过滤。

## 上游新闻（parser: cqcb）

- 栏目页 `https://www.cqcb.com/channel/<id>.html` 为 SSR，稿件路径 `/news/<频道id>/<YYYY-MM-DD>/<id>.html`，**日期可直接从 URL 精确提取**。

## 九派新闻（parser: jiupai_sina）

- 官网 `www.jiupainews.com` 是 React 内容后台（create-react-app + wangeditor + echarts），任意路径都返回同一个约 7KB 空壳，**没有面向读者的公开列表页**；`m.jiupainews.com` 不通，微博移动端 API `m.weibo.cn/api/container/getIndex` 返回 432。
- 降级方案：官方微博在新浪新闻的 SSR 聚合页 `https://sina.cn/media/7516679696`，条目结构为 `<a class="post-link" href="/news/detail/<id>.html">` + `<div class="post-head">` 里的 `.time` + `<div class="post-text">` 正文。
- 正文常以 `【#话题#】` 或连续 `#话题#` 开头，需剥离话题标记后取首句作标题；链接补全为 `https://sina.cn/news/detail/<id>.html`。
- 每条结果备注必须标注来源为「官方微博聚合页」，避免误认为官网直抓。

## 主题标签统一为类别级（2026-11-11）

- 问题：看板标签区出现「用血紧张」这种孤立标签。根因是**两套标签体系混用**——精选样本 `curated` 是早期人工自由标注，共 76 种事件级细标签（用血紧张、献血法、灰色产业链、软裁员、离线权、隐形加班、仅退款、国家赔偿…），而实时抓取 `crawled` 用的是 `keywords` 的 6 个组名。看板 chips 由 `items.flatMap(x=>x.topics)` 直接生成，于是两堆标签混在一起，很多只对应 1～2 条稿。
- 用户要求：「不需要作为一个标签，也不仅仅是用血问题，是把类似的社会新闻涵盖进来」→ 标签应是**能覆盖一类稿件的类别**，不是单个事件的关键词。
- 方案：`normalize_topics()` 用「标题 + 原始 topics + tags_raw」对 `KEYWORDS` 重新匹配，统一输出 6 个组名；`all_items()` 对 curated 与 crawled 都做归一，并给 curated 写 `tags_raw` 保留原始细标签。看板 chips、CSV「主题标签」列随之只剩 6 类。
- 为保证每条精选稿都能归类，给 6 组各补了一批民生词（医疗用血 +14、劳动权益 +14、消费维权 +17、社会保障 +15、公共安全 +15、教育住房 +12），扩词后 38 条精选样本**归类覆盖率 100%**（扩词前只有 32/38）。扩词同时提高实时稿的多标签召回。
- 幂等：`tags_raw` 参与匹配文本，重复运行不会因 topics 已被覆盖而丢失归类依据。
- 验证方向：看板 chips 数应为 6；「用血紧张」不再出现在标签区；「救命血，为何一血难求？」应归入「医疗用血」并与其他医疗民生稿一起被该标签筛出。

## 拓展新闻来源与通用 link_list parser（2026-11-11）

- 新增 `parse_link_list()`，注册为 `parser: link_list`。**拓展源只需改 `news_data.json` 的 `sources` 配置，无需写代码**。字段：`url`、`media` / `column`、`base`、`url_filter`（稿件 URL 正则）、`title_include` / `title_exclude`（标题正反筛选）、`title_max_len`（默认 70，过滤「标题+摘要+[全文]」混合文本）、`date_from_url`（从 URL 抽 `YYYY-MM-DD` 的三组捕获）、`mode`、`max_items`、`recent_only`。`crawl()` 支持按源 `max_items` 覆盖全局 `--max-per-source`。
- 实测可抓（SSR，含中文标题链接）：
  - 界面新闻首页 `https://www.jiemian.com/`（约 99 条）、`/lists/6.html` 互联网日常（37 条）、`m.jiemian.com/lists/644_1.html` 界面消费者报告（20 条历史调查稿库）、`/lists/2.html` 商业（82 条）。稿件 URL `/article/<数字>.html`。
  - 新京报 `https://www.bjnews.com.cn/shendu`（深度，17 条）、`/depth/45.html`（调查热榜，51 条，但混首页导航稿）。稿件 URL `/detail/<数字>.html`。首页 60 条。
  - 人民网社会 `http://society.people.com.cn/`（49 条）与 `/GB/1062/index.html` 社会万象（31 条，多为 2026-06 旧稿）。
  - 大众网 `https://www.dzwww.com/`（141 条，导航文字多需强清洗）。
- 实测不可抓 / 不推荐：腾讯新闻首页、`/ch/society`、`new.qq.com/ch/society`、`/omn/author/...` 全为 CSR 空壳（0 中文标题链接），只有 `rain/a/文章页` 是 SSR；`news.qq.com/rain/a/20261110A038GR00` 那类聚合转载无法用列表源发现。中国新闻周刊 `inewsweek.cn` 编码异常、0 标题；`hnrbp.com` 不是大象新闻（被短剧站占用）；央视 `tv.cctv.com/lm/jdft/` 栏目页稿件链接由 JS 加载。界面 `www.jiemian.com/lists/1.html` 偶发 403，`/lists/644_1.html` PC 版 404（只有移动版可用）。
- **本次新增 3 个自动源**：界面·首页、界面·互联网日常、新京报·深度，均配 `title_include`（消费维权/调查/司法/事件词）与 `title_exclude`（投资早报、A股、收购、证监会、编程工具、AI应用、芯片、早报/日报/盘点、地方新闻精选等），`max_items` 分别 8/6/6。实跑贡献 **9 条干净稿**（医美水光针调包、婚纱店跑路、鲸鱼APP无法提现、AI盗用算力案、共享寄存柜退款难、无罪判决、断亲社会调查等）。
- 教训：直接把泛首页加进采集会带入大量财经/科技/摘要噪声（界面首页 78 条里聚焦过滤只挡掉 10 条）。**必须先 `title_include` 精准收窄，再让聚焦过滤兜底**；`[全文]` 与超长文本要拦掉，否则会把摘要当成标题。

- `channels` 新增「拓展源」组，收录界面消费者报告专题、新京报调查热榜、人民网社会万象、央视焦点访谈等人工入口，便于继续按此模式扩展。

## 社会民生聚焦（过滤政务通知类）

- 需求：用户明确「不需要政务通知类新闻，需要社会民生强相关的事件报道」。看板里混进了政策发布、会议部署、机构宣传、表彰、讣告、时政要闻。
- 判定（`is_social_focus()`）两级，避免过度过滤：
  - `FOCUS_HARD`（命中即排除）：领导人活动与全会精神、发文 / 印发 / 出台 / 条例 / 草案 / 二审、常务会议 / 工作专班 / 挂牌督办 / 举一反三 / 集中整治、宣传周 / 拉开帷幕 / 亮相 / 获授 / 送达 / 表彰 / 逝世 / 秋招、专项规划 / 正式落地 / 新图景等。
  - `FOCUS_SOFT`（命中且标题**没有任何具体人物词**才排除）：活动、会议、发布、通知、方案、规划、措施、政策、走进校园、开展。`FOCUS_PEOPLE` 含男子 / 女子 / 老人 / 学生 / 家长 / 患者 / 消费者 / 骑手 / 教师 / 农民工 / 当事人 / 居民等，用来豁免真正的人物报道（如「警方通报男子…」「学生上课走神…」）。
- **不要用「正向打分」**：2026-11-11 曾试过按人物/事件/民生词打分取阈值，结果把《救命血，为何一血难求？》《职场"软裁员"引争议》《免费"鉴宝"陷阱重重》等核心深度稿一并剔除（41/89），因为这些标题没有具体人物或领域词。**排除式规则比打分安全**。
- 数据不丢：聚焦过滤只作用于 `all_items()` 生成的看板与 CSV；`main()` 去重时用 `all_items(data, apply_focus=False)`，被过滤稿仍完整保存在 `news_data.json`。`--focus 0` 关闭过滤即可查看全量；`data["focus"]` 记录开关与排除条数，看板统计栏显示。
- 实测（89 条）：剔除 17～18 条政务 / 宣传稿（约 20%），核心民生稿全部保留。刻意保留了「警方通报」类有具体人物和事件的稿（如西咸新区政务中心挖掘机破坏），因为那属于社会事件而非政务通知。
- 软内容过滤（用户后续明确「暖闻、校园趣闻、健康科普不需要」）：新增 `FOCUS_FLUFF`，**只对 `form=栏目更新` 的兜底稿生效**，避免误伤深度调查 / 舆论监督里的同类词。词表分三组：暖闻与机构宣传（暖侬心、生命通道、护送、风华正茂、青春之力、守护每一颗心、见义勇为…）、校园趣闻与校园软新闻（花样游泳、吐火术、非遗登台、国旗下、思政课、推迟上学时间、美人鱼、健身学舞…）、健康科普与养生警示（专家提醒、医生谈、隔夜菜、久坐加班、血栓风险、血脂高、险丧命、科普…）。
- 实测（聚焦后 72 条）：`栏目更新` 兜底共 11 条，全部命中 `FOCUS_FLUFF` 并被剔除，看板剩 **61 条且不再有「栏目更新」形态**；《救命血》《软裁员》《免费"鉴宝"》《黑医师》《21车冻货》《政务中心挖掘机破坏》《演出服集体退款》《贺兰山失联》等核心稿全部保留。数据文件仍 89 条，`--focus 0` 看全量。
- 经验：软内容用「限定形态 + 具体短语词表」最安全；不要用「学生 / 老人 / 医生」这类泛化人物词做排除，否则会误删真正的民生事件报道。

## 报道形态自动归类

- 看板「全部形态」下拉的选项由 `const forms = [...new Set(items.map(x=>x.form))]` 从当前数据动态生成，**每次重建看板都会同步刷新**，没有硬编码。
- 但「选项会刷新」不等于「新稿有分类」：早期版本里 `make_item()` 把所有实时抓取稿写死为 `栏目更新`，导致 6 个细分形态只覆盖人工精选样本，点「深度调查」看不到当天新稿。现已修复。
- `FORM_RULES` 按标题关键词顺序匹配，越具体越靠前：评论 → 舆论监督 → 深度调查 → 通报回应 → 个案维权 → 政策服务 → `栏目更新` 兜底。精选样本 `curated` 保留人工标注，不被规则覆盖；`crawled` 每次运行重算，保证分类随数据刷新。
- 2026-11-11 实测（51 条实时稿）：细分 32 条、兜底 19 条（37%）。兜底多为暖闻、校园活动、健康科普、人物趣闻，本就不属于那 6 类，保留「栏目更新」作为「其他动态」是合理的；若要把它们也细分，应新增形态而非硬塞进现有类别。
- 调参：直接改 `scripts/collect_news.py` 顶部的 `FORM_RULES`，注意顺序（例如「通报」很常见，必须排在「个案维权」之前，否则调查稿会被误归为通报）。统计栏会显示「实时稿形态归类 N 条（M 条兜底）」。

## 同题去重

- 目的：同一事件常被多家融媒体 / 官媒转载，标题写法差异很大，旧的「标题前 18 字」规则抓不住（例如「太原一建筑火灾致5人遇难」与「太原公寓火灾已致14人遇难、25人入院治疗」）。
- 算法：标题去标点后取字符 bigram 集合，计算 Jaccard 与重叠系数，取 `max(jaccard, overlap*0.85)`；重叠系数能识别「短标题被长标题包住」。标题完全一致则无条件合并、不受日期限制。
- 三级判定（均要求日期差 ≤ 1 天，无日期放行；用并查集跨「精选样本」与「实时抓取」批次统一聚类）：
  1. 标题完全一致 → 合并；
  2. 相似度 ≥ 0.48 → 合并；
  3. 相似度 0.28～0.48 且共享**实体锚点** → 合并。锚点 = 两条标题的最长公共连续子串，长度 ≥ 3 且不含模板标记 `公安局 / 警情通报 / 发布警情 / 接报辖区 / 2026年 / 11月 / 时许 / 央视新闻 / 新华社客户端`。
- 为什么要锚点：同一事件的不同进展字面差异很大，例如「太原通报火灾救治情况：25人在院治疗，其中危重伤9人重伤4人」与「太原公寓火灾已致14人遇难、25人入院治疗其中9人伤势较重」只有 0.33 分，但共享「院治疗其中」等实体串；而「警方通报政务大厅门头遭破坏」与「杭州警方通报致2死刑案」有 0.45 分，共享的却只是「区公安局发布警情通报2026年11月」这种公文模板，属于不同事件，必须排除。
- 保留优先级：精选样本 > 官媒 > 其它；同级依次取日期更新、**标题中数字更多**（进展稿信息更全）、标题更长的一条。被合并稿的媒体、标题、链接写入主稿 `dup_media` / `dup_urls` / `dup_count`，并在 `note` 追加同题说明；重复稿从数据文件物理剔除，但链接不丢失。看板显示「同题 N 家」标签与可点链接，CSV 多一列「同题报道数」。
- 阈值经验（2026-11-10，110 条样本实测）：只靠高相似阈值会得到 7 簇 / 合并 9 条，漏掉同一事件的不同进展；加上锚点规则后为 **8 簇 / 合并 16 条（110 → 94）**，太原火灾 6 条、21 车冻货 6 条各自收成一簇，三个「公安通报」误判对仍保持独立。`ANCHOR_FLOOR = 0.28` 不要随意调低：0.26 附近已出现「COP31 首日 vs 中国角日程指南」这类同专题但不同事件的串扰。数据规模或选题变化后应重新抽样校准。
- 关闭与调节：`--dedup 0` 关闭，`--dedup 0.55` 更保守（只合并高度相似的转载）。

## 已知坑

| 现象 | 原因 / 对策 |
|---|---|
| Python 请求返回 403 | 高频或 UA 不完整；补浏览器头、每源限速 1.2 秒 |
| 页面能打开但抓不到标题 | 纯 CSR（React/Vue）；改用 SSR 栏目页或官方账号聚合页 |
| 标题尾部带「沸点 2026-11-08」「封面新闻 26天前」「澎湃新闻、某单位」 | 元信息塞在同一个 `<a>`；用 `clean_title` 的 META_RE 与来源词表剥离 |
| 看板里同一事件出现多条 | 跨源转载；按标题前 18 字归一化去重 |
| CSV 写入 PermissionError | 文件被编辑器 / 预览面板占用；`safe_write` 自动退化到 `社会民生新闻样本_最新.csv` 副本 |
| `--days` 过滤后某源为 0 条 | 栏目只有历史稿；给该源设 `recent_only=false` |
| 想看历史稿但列表里没有 | 默认 `--window 30` 已物理剔除超期稿；用 `--window 0` 重新运行 |
| 看板顶部老稿混在新稿里 | 排序只有时间倒序 / 正序，且精选与实时**不分批次统一按日期排**；旧版本曾有「默认顺序（精选→实时）」把上周精选整批顶到最前，已移除。选控件设 `autocomplete="off"`，脚本对浏览器记住的非法值强制回退到最新优先 |
| 不同事件被误合并 | 相似度阈值过低或标题共享「警方通报」等模板词；调高 `--dedup`，必要时 `--dedup 0` |
| 同一事件仍出现多条 | 各稿写法差异过大、相似度低于阈值；适当调低 `--dedup` 并抽样复核 |

## 新增站点步骤

1. 先确认页面是否 SSR：用浏览器工具或 `urllib` 抓 HTML，搜索页面中是否直接出现中文标题与稿件链接。
2. 找出稿件 URL 的稳定模式与标题所在标签，写一个 `parse_<name>(body, source)`，内部逐条调用 `make_item`。
3. 把函数注册到 `PARSERS` 字典。
4. 在 `news_data.json` 的 `sources` 增加配置（含 `parser`、`media`、`column`、`mode`），必要时同步补 `channels` 入口分组。
5. 用 `--out` 指向临时目录实跑一次，检查标题是否干净、日期是否正确、URL 是否可打开，再决定是否设为默认启用。
